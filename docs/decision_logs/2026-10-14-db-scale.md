# Decision log: db_scale fix for the dB random gain (2026-10-14)

**Problem [Fact].** `torchaudio.compliance.kaldi.fbank` returns the natural log of mel power. One fbank unit = 10·log10(e) = 4.343 dB, so 1 dB = 0.2303 fbank units. The AST image is `(fbank − mean) / (2·FBANK_STD)`, so one dB of the raw log-mel is `0.2303 / (2·4.569) = 0.0252` image units.

The code used `db_scale = 1 / (2·FBANK_STD) = 0.1094`, about 4.34× too large. The "6 dB" random per-bin gain (P3, arm `sc_gain`) therefore had an SD of about 26 dB on AST and on DASS.

**Fix.** `DB_PER_NAT = 10 / ln(10)` in `cycles.py`. `db_scale = 1 / (2·FBANK_STD·DB_PER_NAT)` for AST (`encoders/__init__.py`) and DASS (`encoders/dass.py`). HTS-AT and CLAP use librosa dB with `db_scale = 1.0` and are unchanged. Test: `tests/test_db_scale.py` (+6 dB on the waveform moves the AST image by 6·db_scale within 1%). Full suite: 37 passed.

**Deviation to report.** Every `sc_gain` result from the 2026-10-09 report (screening 3-fold and 5-fold, refit seeds 0-4, KAUH control A for `sc_gain`) ran with about 26 dB SD, not the registered 6 dB. These numbers are kept as run and labelled as a deviation. `sc_gain` is rerun after this fix (campaign C0).

**Not affected.** SC (waveform domain), baseline, `sc+sc_static` (AuscultTrust), Freq-MixStyle, HTS-AT.

**Approximation kept.** DASS normalises each cycle by its own std, so the scale is approximate there (existing `ponytail:` note in `dass.py`). The test covers AST only, since a constant gain cancels under per-cycle normalisation.
